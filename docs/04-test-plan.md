# แผนทดสอบ

ทดสอบด้วยบัญชีอย่างน้อย 3 บัญชี: **CEO ทดสอบ**, **พนักงาน A**, **พนักงาน B** (ไม่ใช่ Admin ทั้งคู่)
ทำซ้ำทั้งบน iPhone และ Android ก่อนเปิดใช้จริงทุกครั้งที่แก้ Flow หรือสิทธิ์

## 1. ความลับและสิทธิ์ (ต้องผ่านทั้งหมด ห้ามข้าม)
| # | ขั้นตอน | ผลที่ต้องได้ |
|---|---|---|
| S1 | CEO สั่งงานให้ A แล้ว B เปิดแอป | B ไม่เห็นงานของ A |
| S2 | B เปิด URL ของ List `Tickets` ใน SharePoint ตรง ๆ | ไม่เห็นงานของ A |
| S3 | B เปิด URL รายการของ A ตรง ๆ (`.../DispForm.aspx?ID=<id>`) | Access denied |
| S4 | A เปิดรายการของตัวเองใน SharePoint แล้วพยายามแก้ไข | แก้ไม่ได้ (อ่านอย่างเดียว) |
| S5 | A ค้นหาชื่องานใน Microsoft Search / SharePoint Search | ไม่เห็นงานของคนอื่น |
| S6 | A เรียก Flow `UpdateTicket` ด้วย `ticketId` ของงาน B (เช่น แก้สูตรในแอปสำเนา) | Flow ปฏิเสธ `ok=false` |
| S7 | A เรียก `CreateTicket` | Flow ปฏิเสธ "ไม่มีสิทธิ์สั่งงาน" |
| S8 | A เรียก `UpdateTicket` action `close` บนงานของตัวเอง | Flow ปฏิเสธ |
| S9 | ข้อความแจ้งเตือนบนหน้าจอล็อก | ไม่มีรายละเอียดงาน มีแค่เลข Ticket |

## 2. เส้นทางสถานะ
| # | ขั้นตอน | ผลที่ต้องได้ |
|---|---|---|
| W1 | เดินครบเส้นทาง New → Acknowledged → InProgress → Done → Closed | ทุกขั้นสำเร็จ มีประวัติครบ 5 รายการ และ IsOpen=false หลังปิด |
| W2 | New → InProgress (ข้ามรับทราบ) | สำเร็จ และ `AckedAt` ถูกตั้ง |
| W3 | InProgress → WaitingCEO → (CEO reply) → InProgress | สำเร็จ ทั้งสองฝ่ายได้รับแจ้งเตือน |
| W4 | Done → (CEO reopen) → InProgress | สำเร็จ |
| W5 | พยายาม New → Done ตรง ๆ | ปฏิเสธ |
| W6 | กดปุ่มรับทราบสองครั้งเร็ว ๆ | ได้ประวัติ 1 รายการ ครั้งที่สองได้ `STALE` |
| W7 | A กดเสร็จ ขณะที่ CEO กดยกเลิกพร้อมกันจากอีกเครื่อง | สำเร็จเพียงหนึ่ง อีกฝ่ายได้ `STALE` และแอปโหลดใหม่ |
| W8 | งานที่ Closed แล้ว | ไม่แสดงในรายการ และกดปุ่มใด ๆ ไม่ได้ |

## 3. วันที่และโซนเวลา
| # | ขั้นตอน | ผลที่ต้องได้ |
|---|---|---|
| D1 | มือถือตั้งภาษาไทย (ปฏิทินพุทธศักราช) สร้างงานกำหนดส่ง "พรุ่งนี้" | บันทึกเป็นปี ค.ศ. ที่ถูกต้อง วันตรงกับพรุ่งนี้ |
| D2 | สร้างงานเวลา 23:30 และ 00:30 | `DueDate` ไม่เลื่อนข้ามวัน |
| D3 | ปุ่ม "สิ้นสัปดาห์" ในวันจันทร์ ศุกร์ เสาร์ อาทิตย์ | ได้วันศุกร์ที่ถูกต้อง (วันเสาร์/อาทิตย์ → ศุกร์หน้า) |
| D4 | DailyReminders รันที่ 08:00 ตามเวลาไทย | งานที่เลยกำหนดถูกเตือนครั้งเดียว ไม่ซ้ำในวันถัดไป |
| D5 | นัดหมายส่วนตัวที่สร้างในแอป | เวลาตรงกับใน Outlook และเป็น Private |

## 4. การแจ้งเตือน
| # | ขั้นตอน | ผลที่ต้องได้ |
|---|---|---|
| N1 | CEO สั่งงาน | A ได้รับแจ้งเตือนภายใน 30 วินาที |
| N2 | A รับทราบ | CEO ได้รับแจ้งเตือนภายใน 30 วินาที |
| N3 | แตะการแจ้งเตือน | เปิดแอปไปที่ Ticket นั้นโดยตรง |
| N4 | ผู้ใช้ที่ยังไม่เคยเปิดแอป Power Apps บนมือถือ | Flow ไม่ล้มเหลวทั้ง Flow (การแจ้งเตือนล้มเหลวต้องไม่ทำให้สร้างงานไม่สำเร็จ) |

## 5. ความทนทาน
| # | ขั้นตอน | ผลที่ต้องได้ |
|---|---|---|
| R1 | ปิดอินเทอร์เน็ตแล้วกดสั่งงาน | ปุ่มปิด หรือแสดงข้อผิดพลาด ไม่ได้งานซ้ำเมื่อกลับมาออนไลน์ |
| R2 | ใส่ชื่อผู้รับผิดชอบที่ลาออก (บัญชีถูกปิด) | Flow ปฏิเสธพร้อมเหตุผล |
| R3 | ทำให้ Flow ล้มเหลวโดยตั้งใจ (เช่น เปลี่ยนชื่อคอลัมน์ในสำเนาทดสอบ) | ผู้ดูแลได้รับอีเมลแจ้ง Error และไม่มี Ticket ครึ่ง ๆ กลาง ๆ ค้าง |
| R4 | สร้าง Ticket ทดสอบ 2,100 ใบใน Site ทดสอบ แล้วเปิดแอปด้วยบัญชี CEO | รายการที่เปิดอยู่แสดงครบ ไม่มีคำเตือน Delegation |
| R5 | ชื่องานภาษาไทยยาว 255 ตัวอักษร และมีอีโมจิ | บันทึกและแสดงผลถูกต้อง |

## 6. ใบรับรองการใช้งานจริง
ก่อนเปิดให้พนักงานทั้งหมดใช้: ทดลองกับ CEO + พนักงาน 3–5 คนเป็นเวลา 1 สัปดาห์ และผ่านทุกข้อในหมวด 1 กับ 2
