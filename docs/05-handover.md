# คู่มือดูแลระบบและส่งต่อ

## บทบาท
| บทบาท | ผู้รับผิดชอบ | หน้าที่ |
|---|---|---|
| เจ้าของระบบ | ผู้พัฒนาปัจจุบัน | พัฒนา แก้บั๊ก ตรวจ Flow |
| ผู้ดูแลสำรอง (ฝ่ายธุรกิจ) | คุณ Suchada (COO) | Co-owner ของแอป ทุก Flow และ Site ได้รับอีเมลเมื่อ Flow ล้มเหลว มีอำนาจให้สิทธิ์ชั่วคราวแก่ผู้ช่วยด้านเทคนิคในกรณีฉุกเฉิน และผูก Connection ใหม่ด้วยบัญชีตัวเองได้ถ้าบัญชีเจ้าของระบบใช้ไม่ได้ |
| Tenant Admin | _(ต้องระบุชื่อ Global Admin / SharePoint Admin)_ | อนุมัติสิ่งที่ต้องใช้สิทธิ์ Admin |

## ความเสี่ยงหลักของระบบที่มีผู้ดูแลคนเดียว
1. **Flow ผูกกับบัญชีเจ้าของ:** ถ้าบัญชีถูกปิด ลาออก หรือ Connection หมดอายุ ระบบจะหยุดเงียบ ๆ
   - เพิ่มผู้ดูแลสำรองเป็น Co-owner ของทุก Flow ตั้งแต่วันแรก
   - **ข้อเสนอเพื่อตัดสินใจ:** ใช้บัญชีบริการ (เช่น `ceo-app@<โดเมน>`) เป็นเจ้าของ Connection ต้องมี License M365 1 ที่นั่ง ⚠️ ตรวจเงื่อนไข License ของบัญชีบริการกับ Microsoft/Reseller
2. **สิทธิ์ Site Owners:** Owners เห็นทุก Ticket จำกัดไว้ที่ CEO + เจ้าของระบบ + ผู้ดูแลสำรองเท่านั้น
3. **Trial หมดอายุ:** ห้ามใช้ Dataverse หรือ Connector ที่มาจาก Trial ใด ๆ

## งานประจำ
| ความถี่ | งาน |
|---|---|
| ทุกวันทำการ | ไม่ต้องทำอะไร ถ้ามีอีเมล Error จาก Flow ให้ตรวจภายในวันนั้น |
| ทุกสัปดาห์ | ตรวจว่าได้รับอีเมล `HealthCheck` วันจันทร์ ถ้าไม่ได้ เปิด Run history |
| ทุกเดือน | ตรวจ Run history ของทุก Flow, ตรวจรายชื่อ Site Owners, ตรวจ Connection ที่มีสถานะ Error |
| ทุกไตรมาส | ทดสอบหมวด 1 (ความลับ) ใน [04-test-plan.md](04-test-plan.md) ซ้ำ |
| ทุกปี | ย้าย Ticket ที่ปิดแล้วเกิน 1 ปีไป List เก็บถาวร (`TicketsArchive-<ปี>`) เพื่อคุมจำนวนรายการที่มีสิทธิ์เฉพาะ |
| เมื่อพนักงานลาออก | ปิดงานค้างหรือโอนงาน (ฟีเจอร์โอนงานยังไม่มีในเฟสแรก ให้ CEO ยกเลิกแล้วสั่งใหม่) |

## การเปลี่ยนแปลงระบบ
1. แก้ในสำเนาทดสอบก่อนเสมอ (Site ทดสอบ + แอปสำเนา)
2. ทดสอบตาม [04-test-plan.md](04-test-plan.md) หมวดที่เกี่ยวข้อง
3. Export Solution เป็น `.zip` แล้ว Commit ลง Repo นี้ในโฟลเดอร์ `solution/` พร้อมบันทึกสิ่งที่เปลี่ยน ⚠️ ถ้าใช้ Solution ได้ (ข้อ 10 ของต้นแบบ)
4. เปลี่ยนกติกาสิทธิ์ตามคำสั่ง CEO: แก้ที่ขั้นตอน Grant access ใน `CreateTicket` จุดเดียว และถ้าต้องการให้มีผลกับใบเดิม ต้องทำ Flow ชั่วคราวไล่ตั้งสิทธิ์ใหม่ทุกใบที่เปิดอยู่

## เฟสถัดไป (ยังไม่อยู่ในขอบเขต)
- ผู้ติดตาม (Watchers) ต่อ Ticket
- โอนงานให้ผู้รับผิดชอบคนใหม่
- ข้อมูลจาก SAP B1, Web Sales, Platform บริหารโครงการ, Forecast สำหรับหน้าภาพรวมของ CEO
  - ใช้ **n8n ที่บริษัทมีอยู่แล้ว** เป็นตัวดึงข้อมูลตามรอบเวลา (เช่น SAP B1 Service Layer) แล้วเขียนสรุปลง SharePoint List ให้ Power Apps อ่านด้วย Connector มาตรฐาน ไม่ต้องซื้อ Premium
  - ห้ามให้ Power Apps เรียก n8n ตรง ๆ (ต้องใช้ HTTP/Custom Connector ซึ่งเป็น Premium)
  - กุญแจที่ n8n ใช้เข้า SharePoint ต้องจำกัดสิทธิ์เฉพาะ Site หรือ List ที่จำเป็น และไม่ให้เข้าถึง List `Tickets`
- ช่องทางแจ้งเตือนผ่าน LINE Official Account (Messaging API) ผ่าน n8n ถ้าการแจ้งเตือนแบบอื่นไม่ตอบโจทย์ (ส่งแค่เลข Ticket ไม่ส่งรายละเอียด)
- นำข้อมูลใน SharePoint ไปทำ RAG องค์กร
