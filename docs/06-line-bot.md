# บอท LINE สำหรับ CEO สั่งงาน (n8n)

## ภาพรวม
```
CEO พูดผ่านไมค์บนแป้นพิมพ์ → LINE OA "DF สั่งงาน" → n8n (Webhook)
   → ถามผู้รับผิดชอบ (ปุ่ม) → ถามวันส่ง (ปุ่ม) → สร้าง Ticket ใน SharePoint
   → ตอบ CEO ว่าสร้างแล้ว + แจ้งเตือนพนักงาน (ช่องทางเดิมของ Power Apps)
```
ไม่ใช้ AI ในเฟสแรก ข้อความที่ CEO ส่งคือชื่องานตามที่พูด

## บทสนทนา
| ขั้น | CEO ทำ | บอทตอบ |
|---|---|---|
| 1 | ส่งข้อความ (พูดผ่านไมค์บนแป้นพิมพ์ หรือพิมพ์ หรือ Forward) | 📝 *"<ข้อความ>"* **สั่งใคร?** Quick Reply: คนที่สั่งบ่อยสุด 4–8 คน + [🔍 คนอื่น] + [❌ ยกเลิก] |
| 1a | แตะ [🔍 คนอื่น] | "พิมพ์หรือพูดชื่อเล่น" → CEO ส่งชื่อ → บอทแสดงปุ่มคนที่ชื่อเล่น/ชื่อจริงตรงกันจาก `Employees` (เฉพาะคนที่ยังทำงาน) ถ้าไม่พบ: "ไม่พบ '<ชื่อ>' ลองใหม่" |
| 2 | แตะชื่อผู้รับผิดชอบ | **ส่งเมื่อไร?** [วันนี้] [พรุ่งนี้] [ศุกร์นี้] [📅 เลือกวัน] (Datetime picker แบบ date) |
| 3 | แตะวัน | สร้าง Ticket แล้วตอบ ✅ *สั่งคุณ<ชื่อเล่น> แล้ว · T-<ID> · ส่ง <วันที่>* |
| — | ส่งรูประหว่างขั้น 1–2 | แนบรูปกับงานที่กำลังสร้าง ตอบ "📎 แนบรูปแล้ว" |
| — | ส่งรูปโดยไม่มีงานค้าง | "ส่งข้อความชื่องานก่อน แล้วค่อยส่งรูป" ⚠️ หรือใช้รูปเป็นงานใหม่ชื่อ "งานจากรูป" ให้ CEO ตัดสินในสัปดาห์ทดลอง |
| — | ส่งข้อความเสียงของ LINE | "กรุณากดไมค์บนแป้นพิมพ์แทนการกดค้างไมค์ของ LINE" |
| — | ส่งข้อความใหม่ขณะมีงานค้าง | ยกเลิกงานค้างเดิม แจ้ง "ยกเลิกงานก่อนหน้า: <ชื่อ>" แล้วเริ่มงานใหม่จากข้อความล่าสุด |

ปุ่ม "คนที่สั่งบ่อย" คำนวณจาก Ticket 30 วันล่าสุด ช่วงแรกที่ยังไม่มีข้อมูล ใช้รายชื่อ PM, การตลาด, Presales, Sales ที่กำหนดใน `Config`

## สรุปภาพรวมสำหรับ CEO
| เวลา | เนื้อหา |
|---|---|
| **ทุกวันทำการ 07:00** (Asia/Bangkok) | เปิดอยู่ทั้งหมด · 🔴 เลยกำหนด · ⏳ รอ CEO ตอบ (`WaitingCEO`) · ✅ เสร็จรอปิด (`Done`) · 🆕 ยังไม่รับทราบเกิน `NOACK_HOURS` · สถิติสัปดาห์นี้ (สั่ง/ปิด) พร้อมปุ่ม [ดูงานเลยกำหนด] [ดูงานรอผม] [ดูงานรอปิด] |
| **ทุกวันศุกร์ 17:00** | สรุปรายคน: สั่งสัปดาห์นี้ · ปิดแล้ว · เปิดอยู่ · เลยกำหนด · เวลาเฉลี่ยจากสั่งถึงปิด (วัน) เรียงคนที่มีงานเลยกำหนดมากสุดขึ้นก่อน |
| CEO ส่งคำว่า **"สรุป"** | ตอบสรุปแบบเดียวกับตอนเช้าทันที |

- แตะปุ่มดูรายการ → แสดงไม่เกิน 10 รายการต่อข้อความ รูปแบบ `T-<ID> คุณ<ชื่อเล่น> · <ชื่องาน> · <สถานะ/เลยกำหนด X วัน>` ถ้ามีมากกว่านั้นมีปุ่ม [ดูเพิ่ม]
- รายการ `Done` มีปุ่ม [✅ ปิดงาน] และ [↩️ ส่งกลับ] ให้ CEO ทำจาก LINE ได้ (n8n ตรวจสถานะปัจจุบันก่อนเปลี่ยน แบบเดียวกับ `UpdateTicket`)
- ⚠️ การเปลี่ยนสถานะจาก LINE ต้องเขียน `TicketHistory` และแจ้งเตือนพนักงาน ให้ใช้วิธีเดียวกับ Flow `OnTicketFromLine` (n8n เขียน, Power Automate แจ้งเตือน) ออกแบบรายละเอียดตอนสร้าง Workflow
- **วันทำการ:** ข้ามเสาร์-อาทิตย์ และวันหยุดใน List `Holidays` (คอลัมน์ `Date`, `Title`) ที่ HR ดูแลปีละครั้ง ถ้าวันศุกร์เป็นวันหยุด ยังส่งสรุปรายสัปดาห์ตามปกติ
- ข้อความสรุปเป็น Push message ใช้โควตา OA ราว 30 ข้อความต่อเดือน

1. **ตรวจลายเซ็น Webhook:** คำนวณ HMAC-SHA256 ของ Body ด้วย Channel secret แล้วเทียบกับ Header `x-line-signature` ไม่ตรง → ตอบ 401 และไม่ทำอะไรต่อ
2. **ตรวจผู้ส่ง:** `source.userId` ต้องตรงกับ `CEO_LINE_USER_ID` ใน Config ไม่ตรง → ไม่ตอบ และบันทึก Log (ใครก็แอด OA ได้ถ้าได้ลิงก์ จึงห้ามข้ามข้อนี้)
3. **ตั้งค่า OA:** ปิดการค้นหา ปิดข้อความตอบอัตโนมัติและ Greeting message ของ LINE OA Manager เพื่อไม่ให้ตอบชนกับบอท
4. **เก็บความลับ:** Channel secret และ Channel access token เก็บใน Credentials ของ n8n เท่านั้น ห้ามใส่ใน Workflow หรือ Commit ลง Git
5. **ข้อความถึงพนักงาน:** ใช้ช่องทางแจ้งเตือนเดิม (ไม่ส่งรายละเอียดงานผ่าน LINE ถึงพนักงาน)

## ความทนทานและกันบั๊ก
| ความเสี่ยง | วิธีกัน |
|---|---|
| LINE ส่ง Event ซ้ำ (Redelivery) | เก็บ `webhookEventId` ที่ประมวลผลแล้ว 24 ชั่วโมง ถ้าซ้ำ ข้าม |
| CEO แตะปุ่มซ้ำ | งานร่างถูกใช้แล้วจะถูกลบทันที การแตะครั้งถัดไปตอบ "งานนี้สร้างแล้ว T-<ID>" |
| แตะปุ่มของข้อความเก่า | ข้อมูลในปุ่ม (Postback) มีรหัสงานร่าง ถ้าไม่ตรงกับงานร่างปัจจุบัน ตอบ "ปุ่มนี้หมดอายุแล้ว" |
| งานร่างค้างนาน | หมดอายุใน 30 นาที |
| n8n ช้าเกินอายุ Reply token | ตอบรับทันทีก่อนทำงานหนัก ถ้า Reply ไม่ทัน ใช้ Push message แทน ⚠️ Push ใช้โควตาข้อความของ OA |
| สร้าง Ticket ไม่สำเร็จ | ตอบ CEO ทันทีว่า "❗ สร้างไม่สำเร็จ ลองใหม่หรือใช้แอป" และส่งอีเมลหาผู้ดูแล ห้ามเงียบ |
| n8n ล่มทั้งระบบ | CEO ไม่ได้รับคำตอบภายใน 10 วินาที = รู้ว่าระบบล่ม ใช้หน้าสร้างงานใน Power Apps แทน |

ใช้ **Reply message** (ฟรี) ให้มากที่สุด เพราะทุกการแตะปุ่มของ CEO ได้ Reply token ใหม่ ⚠️ ตรวจเงื่อนไขโควตาข้อความของ LINE OA ปัจจุบัน

## ที่เก็บงานร่าง
งานร่างหนึ่งชิ้น: `draftId`, ข้อความ, รูปที่แนบ, ผู้รับผิดชอบที่เลือก, เวลาเริ่ม
⚠️ เลือกใน n8n ระหว่าง Data tables / Workflow static data / List `Drafts` ใน SharePoint ตามที่ n8n Cloud รองรับ

## เชื่อม n8n → SharePoint (ตัดสินใจแล้ว: App Registration + `Sites.Selected`)
n8n เขียนได้ **เฉพาะ Site `CEO-Tickets`** ผ่าน Microsoft Graph แบบ App-only (Client credentials)

### ขั้นตอนที่ Global Admin ทำ (ครั้งเดียว ประมาณ 15 นาที)
ทำหลังจากสร้าง Site `CEO-Tickets` แล้ว
1. entra.microsoft.com → **App registrations** → **New registration** ชื่อ `DF-CEO-Bot-n8n` แบบ Single tenant
2. **API permissions** → Add → Microsoft Graph → **Application permissions** → `Sites.Selected` → **Grant admin consent**
3. **Certificates & secrets** → New client secret อายุ 24 เดือน แล้ว**กรอกลง Credential ของ n8n โดยตรง** ห้ามส่งทางแชตหรืออีเมล จดวันหมดอายุไว้ใน [05-handover.md](05-handover.md)
4. ให้สิทธิ์เขียนเฉพาะ Site นี้ ผ่าน Graph Explorer (ล็อกอินด้วยบัญชี Global Admin ⚠️ อาจต้อง Consent `Sites.FullControl.All` ให้ Graph Explorer)
   - `GET https://graph.microsoft.com/v1.0/sites/digitalfocusth.sharepoint.com:/sites/CEO-Tickets` → จด `id`
   - `POST https://graph.microsoft.com/v1.0/sites/{id}/permissions`
     ```json
     {"roles": ["write"], "grantedToIdentities": [{"application": {"id": "<Application (client) ID>", "displayName": "DF-CEO-Bot-n8n"}}]}
     ```
5. ส่ง **Tenant ID** และ **Application (client) ID** ให้ผู้พัฒนา (สองค่านี้ไม่ใช่ความลับ)

### หน้าที่ที่แบ่งกัน
- **n8n:** อ่าน `Employees` และ `Config`, สร้างรายการใน `Tickets` (`Source = LINE`, `PermsSet = false`, `Status = New`, `IsOpen = true`) และ `TicketHistory` แล้วได้เลข Ticket ทันทีเพื่อตอบ CEO
- **Power Automate (`OnTicketFromLine` ใน [03-flows.md](03-flows.md)):** ตั้งสิทธิ์รายรายการและแจ้งเตือนพนักงาน เพราะ Graph ตั้งสิทธิ์รายรายการของ List ไม่ได้โดยตรง พนักงานได้แจ้งเตือนช้าลงประมาณ 1–5 นาที (ยอมรับแล้ว)
