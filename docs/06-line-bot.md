# บอท LINE สำหรับ CEO สั่งงาน (n8n)

## ภาพรวม
ไฟล์ Workflow และวิธีติดตั้ง: [../n8n/README.md](../n8n/README.md)

```
CEO พูดผ่านไมค์บนแป้นพิมพ์ → LINE OA "DF สั่งงาน" → n8n (Webhook)
   → ถามผู้รับผิดชอบ (ปุ่ม) → ถามวันส่ง (ปุ่ม) → สร้าง Ticket ใน SharePoint
   → ตอบ CEO ว่าสร้างแล้ว + แจ้งเตือนพนักงาน (ช่องทางเดิมของ Power Apps)
```
ไม่ใช้ AI ในเฟสแรก ข้อความที่ CEO ส่งคือชื่องานตามที่พูด

## บทสนทนา
| ขั้น | CEO ทำ | บอทตอบ |
|---|---|---|
| 1 | ส่งข้อความ (พูดผ่านไมค์บนแป้นพิมพ์ หรือพิมพ์ หรือ Forward) | 📝 *"<ข้อความ>"* **สั่งใคร?** Quick Reply: คนที่สั่งบ่อยสุด 4–8 คน + [🔍 คนอื่น] + [❌ ยกเลิก] |
| 1a | แตะ [🔍 คนอื่น] | "พิมพ์หรือพูดชื่อเล่น" → CEO ส่งชื่อ → บอทแสดงปุ่มคนที่ชื่อเล่น/ชื่อจริงตรงกันจาก `Employees` (เฉพาะคนที่ยังทำงาน) ถ้าไม่พบ: "ไม่พบ '<ชื่อ>' ลองใหม่" |
| 1b | พิมพ์หรือพูดชื่อ เช่น "สั่งแตน" "แตนบัญชี" "ให้คุณมะลิ" | ตรงคนเดียว (ชื่อ หรือชื่อ+แผนก) ไปขั้น 2 ทันที · ตรงหลายคนหรือแผนกไม่ตรง แสดงปุ่มคนที่ชื่อตรง · มีคำว่า "สั่ง/ให้" แต่ไม่พบชื่อ แจ้ง "ไม่พบชื่อ" พร้อมปุ่มเดิม · ข้อความอื่นภายใน 60 วินาทีเป็นรายละเอียดงาน ตอบ "➕ เพิ่มเป็นรายละเอียด" พร้อมปุ่มเดิม (ปุ่ม Quick reply หายทุกครั้งที่ CEO ส่งข้อความ) |
| 2 | แตะชื่อผู้รับผิดชอบ | **ส่งเมื่อไร?** [วันนี้] [พรุ่งนี้] [ศุกร์นี้] [📅 เลือกวัน] (Datetime picker แบบ date) |
| 3 | แตะวัน หรือพูด "พรุ่งนี้" "ศุกร์นี้" "จันทร์หน้า" | สร้าง Ticket แล้วตอบ ✅ *สั่งคุณ<ชื่อเล่น> แล้ว · T-<ID> · ส่ง <วันที่>* |
| — | ส่งรูประหว่างขั้น 1–2 | แนบรูปกับงานที่กำลังสร้าง ตอบ "📎 แนบรูปแล้ว" |
| — | ส่งรูปโดยไม่มีงานค้าง (ส่งรูปก่อนข้อความ) | เก็บรูปไว้ 10 นาที ตอบ "📎 รับรูปแล้ว พิมพ์หรือพูดชื่องานต่อได้เลย" แล้วแนบกับงานถัดไป ถ้าเพิ่งสร้างงานไปไม่เกิน 10 นาที บอกด้วยว่ารูปนี้ไม่ได้แนบกับงานนั้น (แนบรูปเพิ่มให้งานที่สร้างแล้วยังทำไม่ได้) |
| — | ส่งข้อความเสียงของ LINE | "กรุณากดไมค์บนแป้นพิมพ์แทนการกดค้างไมค์ของ LINE" |
| — | ส่งข้อความใหม่ขณะมีงานค้าง | ยกเลิกงานค้างเดิม แจ้ง "ยกเลิกงานก่อนหน้า: <ชื่อ>" แล้วเริ่มงานใหม่จากข้อความล่าสุด |

ปุ่ม "คนที่สั่งบ่อย" คำนวณจาก Ticket 30 วันล่าสุด ช่วงแรกที่ยังไม่มีข้อมูล ใช้รายชื่อ PM, การตลาด, Presales, Sales ที่กำหนดใน `Config`

## สรุปภาพรวมสำหรับ CEO
| เวลา | เนื้อหา |
|---|---|
| **ทุกวันทำการ 07:00** (Asia/Bangkok) | เปิดอยู่ทั้งหมด · 🔴 เลยกำหนด · ⏳ รอ CEO ตอบ (`WaitingCEO`) · ✅ เสร็จรอปิด (`Done`) · 🆕 ยังไม่รับทราบเกิน `NOACK_HOURS` · สถิติสัปดาห์นี้ (สั่ง/ปิด) พร้อมปุ่ม [ดูงานเลยกำหนด] [ดูงานรอผม] [ดูงานรอปิด] |
| **ทุกวันศุกร์ 17:00** | สรุปรายคน: สั่งสัปดาห์นี้ · ปิดแล้ว · เปิดอยู่ · เลยกำหนด · เวลาเฉลี่ยจากสั่งถึงปิด (วัน) เรียงคนที่มีงานเลยกำหนดมากสุดขึ้นก่อน |
| CEO ส่งคำว่า **"สรุป"** | ตอบสรุปแบบเดียวกับตอนเช้าทันที |

- แตะปุ่มดูรายการ → แสดงไม่เกิน 10 รายการต่อข้อความ รูปแบบ `T-<ID> คุณ<ชื่อเล่น> · <ชื่องาน> · <สถานะ/เลยกำหนด X วัน>` ถ้ามีมากกว่านั้นมีปุ่ม [ดูเพิ่ม]
- รายการ `Done` มีปุ่ม [✅ ปิดงาน] และ [↩️ ส่งกลับ] ให้ CEO ทำจาก LINE ได้ (n8n ตรวจสถานะปัจจุบันก่อนเปลี่ยน แบบเดียวกับ `UpdateTicket`)
- การปิดหรือส่งกลับจาก LINE: n8n แก้ `Tickets` และเขียน `TicketHistory` (`Action = close/reopen`, `Processed = false`) แล้ว Flow `OnLineEvent` แจ้งเตือนพนักงาน
- **วันทำการ:** ข้ามเสาร์-อาทิตย์ และวันหยุดใน List `Holidays` (คอลัมน์ `Date`, `Title`) ที่ HR ดูแลปีละครั้ง ถ้าวันศุกร์เป็นวันหยุด ยังส่งสรุปรายสัปดาห์ตามปกติ
- ข้อความสรุปเป็น Push message ใช้โควตา OA ราว 30 ข้อความต่อเดือน

## พนักงานอัปเดต → CEO ได้แจ้งเตือนใน LINE ทันที
แจ้งเฉพาะเรื่องที่ CEO ต้องทำอะไร (ตัดสินใจแล้ว: ทางเลือก C)
| พนักงานกดในแอป | CEO ได้ใน LINE | ปุ่ม |
|---|---|---|
| ถาม CEO (`wait`) | ⏳ คุณ<ชื่อ> รอคำตอบจากคุณ + คำถาม | [💬 ตอบ] |
| ทำเสร็จแล้ว (`done`) | ✅ คุณ<ชื่อ> ทำเสร็จแล้ว รอคุณตรวจ | [✅ ปิดงาน] [↩️ ส่งกลับ] [💬 ตอบ] |
| ส่งความเห็น (`comment`) | 💬 คุณ<ชื่อ> เรื่อง T-<ID> + ความเห็น | [💬 ตอบ] |
| รับทราบ / เริ่มทำ | ไม่แจ้ง ดูในสรุปเช้า | |

**ทำงานอย่างไร:** Power Automate เรียก n8n ตรงไม่ได้ (ต้องใช้ HTTP แบบ Premium) จึงใช้ **SharePoint webhook** บน List `TicketHistory`: ทุกครั้งที่ List เปลี่ยน SharePoint เรียก n8n (`/webhook/ceo-sp-hook`) → n8n ตรวจ `clientState` → อ่านรายการที่ `CEOPending = true` → ส่งเข้า LINE ของ CEO → ตั้ง `CEOPending = false`
- n8n รันเฉพาะเมื่อมีการเปลี่ยนแปลง ไม่ต้องคอยเช็กทุกนาที (ประหยัดโควตาการรันของ n8n Cloud)
- **Webhook หมดอายุภายใน 180 วัน:** สร้างและต่ออายุด้วย [`setup/create-webhook.js`](../setup/create-webhook.js) Flow `DailyReminders` เตือนผู้ดูแลล่วงหน้า 14 วัน ถ้าหมดอายุ CEO ยังเห็นเรื่องเหล่านี้ในสรุปเช้า แต่ไม่ได้แจ้งทันที
- ข้อความถึง CEO มีชื่องานและคำถามของพนักงาน (CEO ใช้ LINE เป็นช่องทางหลักอยู่แล้ว)

**CEO ตอบจาก LINE:** แตะ [💬 ตอบ] → พูดผ่านไมค์บนแป้นพิมพ์ → ส่ง ถ้างานอยู่ในสถานะรอ CEO จะกลับเป็น "กำลังทำ" อัตโนมัติ (`reply`) ถ้าไม่ใช่จะบันทึกเป็นความเห็น (`comment`) แล้ว Flow `OnLineEvent` แจ้งพนักงานทาง Teams ข้อความถัดไปหลังตอบจะเป็นงานใหม่ตามปกติ พิมพ์ "ยกเลิก" เพื่อยกเลิกการตอบ

## ความปลอดภัย
1. **ตรวจลายเซ็น Webhook:** คำนวณ HMAC-SHA256 ของ Body ด้วย Channel secret แล้วเทียบกับ Header `x-line-signature` ไม่ตรง → ไม่ทำอะไรต่อ (n8n ตอบ LINE ว่าได้รับแล้วทันทีตั้งแต่ก่อนตรวจ)
2. **ตรวจผู้ส่ง:** `source.userId` ต้องตรงกับ `CEO_LINE_USER_ID` ใน Config ไม่ตรง → ไม่ตอบ และบันทึก Log (ใครก็แอด OA ได้ถ้าได้ลิงก์ จึงห้ามข้ามข้อนี้)
3. **ตั้งค่า OA:** ปิดการค้นหา ปิดข้อความตอบอัตโนมัติและ Greeting message ของ LINE OA Manager เพื่อไม่ให้ตอบชนกับบอท
4. **เก็บความลับ:** Channel secret, Channel access token, Client secret และ `SP_WEBHOOK_CLIENT_STATE` เก็บใน n8n Variables (หรือ environment variable) เท่านั้น ห้ามใส่ในโค้ดของ Workflow หรือ Commit ลง Git
6. **SharePoint webhook:** n8n ประมวลผลเฉพาะการเรียกที่ `clientState` ตรงกับ `SP_WEBHOOK_CLIENT_STATE` และไม่เชื่อข้อมูลใน Body (อ่านข้อมูลจริงจาก SharePoint เองเสมอ)
5. **ข้อความถึงพนักงาน:** ใช้ช่องทางแจ้งเตือนเดิม (ไม่ส่งรายละเอียดงานผ่าน LINE ถึงพนักงาน)

## ความทนทานและกันบั๊ก
| ความเสี่ยง | วิธีกัน |
|---|---|
| LINE ส่ง Event ซ้ำ (Redelivery) | เก็บ `webhookEventId` ที่ประมวลผลแล้ว 24 ชั่วโมง ถ้าซ้ำ ข้าม |
| CEO แตะปุ่มซ้ำ | งานร่างถูกใช้แล้วจะถูกลบทันที การแตะครั้งถัดไปตอบ "งานนี้สร้างแล้ว T-<ID>" |
| แตะปุ่มของข้อความเก่า | ข้อมูลในปุ่ม (Postback) มีรหัสงานร่าง ถ้าไม่ตรงกับงานร่างปัจจุบัน ตอบ "ปุ่มนี้หมดอายุแล้ว" |
| งานร่างค้างนาน | หมดอายุใน 30 นาที |
| n8n ช้าเกินอายุ Reply token | ตอบรับทันทีก่อนทำงานหนัก ถ้า Reply ไม่ทัน ใช้ Push message แทน ⚠️ Push ใช้โควตาข้อความของ OA |
| สร้าง Ticket ไม่สำเร็จ | ตอบ CEO ทันทีว่า "❗ สร้างไม่สำเร็จ ลองใหม่หรือใช้แอป" และส่งอีเมลหาผู้ดูแล ห้ามเงียบ |
| n8n ล่มทั้งระบบ | CEO ไม่ได้รับคำตอบภายใน 10 วินาที = รู้ว่าระบบล่ม ใช้หน้าสร้างงานใน Power Apps แทน |

ใช้ **Reply message** (ฟรี) ให้มากที่สุด เพราะทุกการแตะปุ่มของ CEO ได้ Reply token ใหม่ ⚠️ ตรวจเงื่อนไขโควตาข้อความของ LINE OA ปัจจุบัน

## ที่เก็บงานร่าง
งานร่างหนึ่งชิ้น: `draftId`, ข้อความ, รูปที่แนบ, ผู้รับผิดชอบที่เลือก, เวลาเริ่ม
ใช้ Workflow static data ของ n8n (ทำงานเฉพาะตอน Workflow เปิดใช้งาน ไม่ใช่ตอนกดทดสอบ)
⚠️ n8n บันทึก static data ทั้งก้อนตอนจบแต่ละ Execution ถ้าข้อความสองข้อความมาถึงในเวลาใกล้กันมาก (ไม่ถึง ~1 วินาที) และ LINE ส่งแยกกันคนละ Webhook ทั้งสอง Execution จะเขียนทับกัน ข้อมูลของอันหนึ่ง (เช่น รูปหรือรายละเอียด) อาจหาย ข้อความที่ LINE ส่งมาใน Webhook เดียวกันไม่มีปัญหา จึงแนะนำ CEO ให้รอบอทตอบก่อนส่งข้อความถัดไป (อยู่ใน "วิธีใช้") ถ้าพบบ่อยในการใช้จริงต้องย้ายงานร่างไปเก็บที่อื่น

## เชื่อม n8n → SharePoint (ตัดสินใจแล้ว: App Registration + `Sites.Selected`)
n8n เขียนได้ **เฉพาะ Site `CEO-Tickets`** ผ่าน Microsoft Graph แบบ App-only (Client credentials)

### ขั้นตอนตั้งค่า (ครั้งเดียว)
ทำหลังจากสร้าง Site `CEO-Tickets` แล้ว

**ผู้พัฒนาทำเอง** (ผู้ใช้ทั่วไปสร้าง App Registration ได้)
1. entra.microsoft.com → **App registrations** → **New registration** ชื่อ `DGF-CEO-Bot-n8n` แบบ Single tenant
2. **API permissions** → Add → Microsoft Graph → **Application permissions** → `Sites.Selected`
3. **Certificates & secrets** → New client secret อายุ 24 เดือน แล้ว**กรอกลง n8n โดยตรง** ห้ามส่งทางแชตหรืออีเมล จดวันหมดอายุไว้ใน [05-handover.md](05-handover.md)

**Global Admin ทำ** (ต้องใช้สิทธิ์ Global Admin)
4. API permissions → **Grant admin consent for Digital Focus** → ตรวจว่า Status เป็น ✅ Granted
5. ให้สิทธิ์เขียนเฉพาะ Site นี้ ผ่าน Graph Explorer (ล็อกอินด้วยบัญชี Global Admin ถ้าไม่มีสิทธิ์ ให้ Consent `Sites.FullControl.All` ในแท็บ Modify permissions)
   - `GET https://graph.microsoft.com/v1.0/sites/digitalfocusth.sharepoint.com:/sites/CEO-Tickets` → จด `id`
   - `POST https://graph.microsoft.com/v1.0/sites/{id}/permissions`
     ```json
     {"roles": ["write"], "grantedToIdentities": [{"application": {"id": "<Application (client) ID>", "displayName": "DGF-CEO-Bot-n8n"}}]}
     ```
6. ถ้าข้อ 5 ยังไม่ได้ทำ บอทจะได้ Error `403` / `accessDenied` ตอนอ่าน List

### หน้าที่ที่แบ่งกัน
- **n8n:** อ่าน `Employees`, `Config`, `Holidays` และ `Tickets` สร้างรายการใน `Tickets` (`Source = LINE`, `PermsSet = false`, `Status = New`, `IsOpen = true`, `AssigneeEmail`) อัปโหลดรูปไป `TicketFiles/T-<ID>` และเขียน `TicketHistory` (`Processed = false`) แล้วตอบเลข Ticket ให้ CEO ทันที
- **Power Automate (`OnLineEvent` ใน [03-flows.md](03-flows.md)):** ตั้งสิทธิ์รายรายการและแจ้งเตือนพนักงาน เพราะ Graph ตั้งสิทธิ์รายรายการของ List ไม่ได้โดยตรง พนักงานได้แจ้งเตือนช้าลงประมาณ 1–5 นาที (ยอมรับแล้ว)
