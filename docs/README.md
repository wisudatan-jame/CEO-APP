# CEO-APP — ระบบสั่งงานและติดตามงานของ CEO

เอกสารออกแบบสำหรับแอปที่ CEO ใช้สั่งงานพนักงานรายคน ติดตามความคืบหน้า และดูปฏิทินส่วนตัว
สร้างบน Microsoft 365 ที่บริษัทมีอยู่แล้ว (Power Apps + SharePoint List + Power Automate)

> สถานะ: **ร่างออกแบบ** ยังไม่ได้ทดสอบกับ Tenant จริง หัวข้อที่มี ⚠️ ต้องยืนยันในขั้นต้นแบบ ([00-prototype.md](00-prototype.md))

## ข้อตัดสินใจที่ตกลงกันแล้ว
1. **ผู้ใช้หลัก:** CEO (คุณสมชาย ประจักษ์สูตร์) สั่งงานและติดตามงาน พนักงานราว 80 คนรับงานและอัปเดต
2. **ขอบเขตเฟสแรก:** ระบบ Ticket ของ CEO + ปฏิทินส่วนตัวของ CEO เท่านั้น ข้อมูล SAP B1, Pipeline, KPI, Forecast ไว้เฟสหลัง
3. **แพลตฟอร์ม:** Power Apps (Canvas) ติดตั้งผ่านแอป Power Apps แล้วตั้งทางลัดบนหน้าจอโฮม (ไม่ทำแอปที่มีไอคอนของตัวเอง ไม่ผ่าน App Store / Google Play)
4. **ที่เก็บข้อมูล:** SharePoint List ใน Site แยกเฉพาะแอปนี้ **ไม่ใช้ Dataverse** (ที่ Tenant ปัจจุบันเป็น Trial จะหมดอายุ)
5. **License:** ใช้เฉพาะ Connector ระดับมาตรฐานที่ Microsoft 365 Business Standard รองรับ ห้ามใช้ Connector แบบ Premium
6. **Ticket:** ผู้รับผิดชอบ 1 คนต่อ 1 ใบ สถานะ ใหม่ → รับทราบ → กำลังทำ → รอ CEO → เสร็จ แล้ว CEO ปิดงานเอง ("รอ CEO" = พนักงานรอคำตอบจาก CEO, "เสร็จ" = รอ CEO ตรวจ — ยืนยันแล้ว)
7. **ปฏิทิน:** อ่านและสร้างนัดในปฏิทิน M365 ของ CEO ด้วยสิทธิ์ของ CEO เอง นัดส่วนตัวตั้งเป็น Private วันกำหนดส่งของ Ticket แสดงเฉพาะในแอป ไม่เขียนลงปฏิทิน M365
8. **ความลับ:** Ticket ทุกใบถือเป็นความลับ เห็นได้เฉพาะ CEO กับผู้รับผิดชอบของใบนั้น สิทธิ์ตั้งโดย Flow จุดเดียว ปรับกฎได้ตามคำสั่ง CEO
9. **ผู้พัฒนาและดูแล:** เจ้าของโปรเจกต์ (คนเดียว) จึงต้องมีผู้ดูแลสำรองและเอกสารส่งต่อ

10. **กลุ่มทดลอง:** CEO, PM, การตลาด, Presales, Sales และคุณ Suchada 1 สัปดาห์ CEO สั่งงานผ่านแอปเท่านั้น
11. **คู่แข่งตัวจริงคือ LINE:** หน้าสร้างงานต้องเร็วพอ ๆ กับพิมพ์ LINE (เกณฑ์ไม่เกิน 15 วินาที)

12. **CEO สั่งงานผ่าน LINE (ขั้น 1B) ทำทันที:** CEO สั่งงานด้วยเสียง > Forward > รูป > พิมพ์ จึงให้ LINE Official Account ของบริษัท + n8n รับคำสั่ง ถอดเสียง แยกผู้รับผิดชอบ/งาน/กำหนดส่ง แล้ว**ให้ CEO กดยืนยันใน LINE ก่อนสร้าง Ticket ทุกครั้ง** Power Apps ใช้สำหรับพนักงานอัปเดตงานและ CEO ดูภาพรวม ส่วนหน้าสร้างงานใน Power Apps เป็นช่องทางสำรองเมื่อบอทล่ม
13. **ที่รัน n8n:** ระหว่างพัฒนาและทดลองใช้โน้ตบุ๊กของผู้พัฒนา (Cloudflare Tunnel, ห้าม Sleep, เปิด BitLocker) ก่อนใช้งานจริงย้ายไป **n8n Cloud**
14. บอทต้องตอบรับใน LINE ทันทีทุกครั้ง เพื่อให้ CEO รู้ทันทีถ้าระบบล่ม (ไม่เงียบหาย)
15. **บัญชี LINE:** เปิด **LINE Official Account ใหม่แยกเฉพาะงานสั่งงาน** (ไม่ใช้ OA การตลาด) ใช้ Messaging API ตั้งค่าให้ค้นหาไม่ได้ และบอทตอบเฉพาะ LINE user ID ของ CEO CEO ใช้งานเหมือนแชตกับเพื่อน: กดค้างไมค์แล้วพูด, Forward หรือส่งรูป ห้ามใช้บัญชี LINE ส่วนตัวกับระบบอัตโนมัติ (ผิดเงื่อนไข LINE)
16. **วิธีพูดสั่งงาน:** CEO กด**ไมค์บนแป้นพิมพ์**ในแชต LINE ให้มือถือแปลงเสียงเป็นข้อความ ตรวจแล้วกดส่ง ถ้าส่งข้อความเสียงของ LINE มา บอทตอบให้ใช้ไมค์บนแป้นพิมพ์แทน
17. **ไม่ใช้ AI ในเฟสแรก:** บอทใช้ข้อความที่ CEO ส่งเป็นชื่องาน แล้วให้ CEO **แตะปุ่มเลือกผู้รับผิดชอบและวันส่ง** (พูด 1 ครั้ง + แตะ 2 ครั้ง) ไม่มีค่า AI ไม่ส่งข้อความลับไปผู้ให้บริการเพิ่ม และแทบไม่มีโอกาสสั่งผิดคน เพิ่ม AI ภายหลังได้โดยไม่ต้องรื้อระบบ รายละเอียดใน [06-line-bot.md](06-line-bot.md)
19. **n8n → SharePoint:** App Registration `DGF-CEO-Bot-n8n` สิทธิ์ `Sites.Selected` เขียนได้เฉพาะ Site `CEO-Tickets` ✅ ตั้งเสร็จ 24 ต.ค. 2026 (Admin consent + สิทธิ์ `write` เฉพาะ Site นี้) ขั้นตอนใน [06-line-bot.md](06-line-bot.md)
20. **ความเร็วเมื่อสั่งผ่าน LINE:** CEO ได้เลข Ticket ทันที ส่วนพนักงานได้แจ้งเตือนช้าลงประมาณ 1–5 นาที (Flow ตั้งสิทธิ์และแจ้งเตือนหลังเห็นรายการใหม่) ยอมรับได้ในช่วงทดลอง วัดเวลาจริงในสัปดาห์ทดลอง
21. **ภาพรวมสำหรับ CEO:** หลักอยู่ใน LINE: สรุปเช้า **ทุกวันทำการ 07:00** (เลยกำหนด → รอ CEO ตอบ → เสร็จรอปิด → ยังไม่รับทราบ → สถิติสัปดาห์) และ **สรุปรายคนทุกวันศุกร์ 17:00** พิมพ์/พูด "สรุป" เมื่อไรก็ได้ ส่วนรายละเอียดดูที่หน้า Dashboard ใน Power Apps ไม่ใช้ Power BI (ไม่มี License)
18. **รายชื่อพนักงาน:** SharePoint List `Employees` (ชื่อจริง นามสกุล ชื่อเล่น ชื่อเรียกอื่น อีเมล แผนก สถานะทำงาน) **HR เป็นเจ้าของและอัปเดต** ถ้าใช้สร้างปุ่มเลือกผู้รับผิดชอบและค้นหาด้วยชื่อเล่น

22. **ช่องทางแจ้งเตือนช่วงแรก:** Microsoft Teams (Flow bot) ส่งเลขงานพร้อมลิงก์เปิดแอป ไม่ใส่ชื่องาน เพราะแสดงบนหน้าจอล็อก

23. **พนักงานอัปเดต → CEO:** แจ้งใน LINE ทันทีเฉพาะ ถาม CEO / ทำเสร็จ / ความเห็น พร้อมปุ่มตอบ ปิดงาน ส่งกลับ ส่วนรับทราบ/เริ่มทำดูในสรุปเช้า ใช้ SharePoint webhook (ต่ออายุทุก 5 เดือน) แทนการให้ n8n คอยเช็ก

24. **ลำดับงานต่อจากนี้:** (1) แอปพนักงาน + บอท LINE สั่งงาน → ทดลองกับ CEO 1 สัปดาห์ (2) **LINE ตอบคำถามอิสระด้วย AI** (3) ปฏิทิน: พนักงานเห็นว่า CEO ว่างหรือไม่ว่าง + ขอนัด + CEO อนุมัติ (4) รวมปฏิทินส่วนตัวของ CEO โดยไม่ให้นัดซ้อนกัน

25. **AI ตอบคำถาม CEO (ขอบเขตแรก):** ตอบจาก (A) ข้อมูลงานใน SharePoint และ (E) ปฏิทิน M365 ของ CEO เท่านั้น AI อ่านอย่างเดียว ห้ามสร้าง/แก้ข้อมูล และต้องอ้างเลขงาน (T-xx) ทุกครั้ง ถ้าไม่มีข้อมูลให้ตอบว่าไม่ทราบ ห้ามเดา · ยอดขาย SAP B1, สต็อก, Platform บริหารโครงการ ไว้ทีหลัง

26. **ผู้ให้บริการ AI:** OpenAI API บนบัญชีเดียวกับ ChatGPT ของ CEO (ระบบนี้เป็นของ CEO โดยตรง) ค่า API แยกจากค่าสมาชิก ChatGPT · CEO เชิญผู้พัฒนาและคุณ Suchada เป็น Owner ของ Organization · ผู้พัฒนาสร้าง Project `CEO-LINE-Bot` ตั้งวงเงินรายเดือน และสร้าง API key ใส่ n8n โดยตรง

27. **AI ตอบเฉพาะข้อมูลในระบบ** (ยืนยันแล้ว แทนแบบตอบความรู้ทั่วไป): ขอบเขต = งานใน SharePoint + ปฏิทิน M365 ของ CEO เท่านั้น ไม่รวมอีเมลและไฟล์ · ทุกคำตอบอ้าง T-xx หรือวันเวลานัด · ไม่มีข้อมูล = ตอบว่า "ไม่พบข้อมูลในระบบ" · คำถามนอกขอบเขต (แปล ร่างข้อความ ความรู้ทั่วไป) ตอบว่าถามได้เฉพาะเรื่องงานและปฏิทิน
28. **แยก "สั่งงาน" กับ "คำถาม" (วิธี D):** ข้อความที่ขึ้นต้นด้วย "ถาม" หรือมี "?" = คำถาม ส่งให้ AI · ข้อความอื่น = สั่งงานตามเดิม โดยหน้า "สั่งใคร?" มีปุ่ม [❓ นี่คือคำถาม] แก้ได้ด้วยการแตะครั้งเดียว · Rich menu มีปุ่ม [❓ ถาม] · งานถูกสร้างเฉพาะเมื่อเลือกคนและวันแล้วเท่านั้น (แตะหรือพูดก็ได้ ข้อ 29)
29. **พูดชื่อและวันส่งได้ (จากการทดสอบ 24 ต.ค.):** ที่ "สั่งใคร?" พูด "สั่งแตน" หรือ "แตนบัญชี" ได้ ชื่อตรงคนเดียวไปต่อทันที ไม่ตรงแสดงปุ่มหรือแจ้งไม่พบ บอทไม่เงียบ · ที่ "ส่งเมื่อไร?" พูด "พรุ่งนี้" "ศุกร์นี้" "จันทร์หน้า" ได้ · ส่งรูปก่อนข้อความได้ (เก็บไว้ 10 นาที) · แนบรูปเพิ่มให้งานที่สร้างแล้วยังทำไม่ได้
30. **โอนงานของคนที่ลาออก:** CEO โอนผ่าน LINE สรุปแจ้งเตือนอัตโนมัติเมื่อ HR ตั้ง `Active = No` และโอนงานค้างทั้งหมดของคนนั้นทีเดียว · งานที่โอนเริ่มใหม่เป็น `New` วันส่งเดิม · ตัดสิทธิ์คนเดิมทันที คนใหม่เห็นงาน รูป และประวัติเดิม ([06-line-bot.md](06-line-bot.md), [คู่มือ ก ข้อ 6](guides/A-flow-onlineevent.md))
31. **สิทธิ์ Site:** พนักงานกดลิงก์ใน Teams แล้วเห็นเฉพาะงานของตัวเอง · เพิ่มคนและแชร์ได้เฉพาะ Site Owners (CEO, ผู้พัฒนา, คุณ Suchada) · ปิดลิงก์ "ทุกคนในบริษัท" ของ Site นี้ ([คู่มือ จ](guides/E-site-lockdown.md))
32. **CEO ตรวจงาน:** งานที่พนักงานกดทำเสร็จ CEO กด ✅ ผ่าน (ปิดงาน) หรือ ❌ ไม่ผ่าน (ส่งกลับเป็นกำลังทำ แล้วพิมพ์/พูดสิ่งที่ต้องแก้ส่งถึงพนักงาน) จาก LINE
33. **ปุ่มสถานะของพนักงาน:** ไม่บังคับลำดับ (กดทำเสร็จได้เลย) แต่ย้อนกลับไม่ได้ · ปุ่มแสดงตลอด แดงทึบ = กดได้ พื้นขาวมี ✓ = ทำแล้ว · ส่งความเห็นได้ไม่จำกัดจนกว่างานปิด · ถาม CEO ได้อีกหลัง CEO ตอบ
34. **พนักงานส่งไฟล์งาน:** แนบในแอป (Excel, PDF, Word, รูป ครั้งละ 5 ไฟล์ ไฟล์ละ 20 MB) เก็บใน `TicketFiles/T-<เลข>` ผ่าน Flow `AttachTicketFile` · CEO ได้ LINE พร้อมลิงก์โฟลเดอร์ ([คู่มือ ฉ](guides/F-attach-files.md))

## เรื่องที่ยังเปิดอยู่

- ตัดสินใจเรื่องบัญชีบริการ (Service account) สำหรับเป็นเจ้าของ Flow ดู [05-handover.md](05-handover.md)
- ลบ Trial ที่ไม่ใช้ออกจากบัญชี (Power Apps Plan 2 Trial, Power Pages vTrial, Copilot Studio Viral Trial, Copilot for Finance Trial) และตรวจว่าไม่มีงานจริงอยู่ใน Developer environment หรือ Dataverse for Teams (ทั้งสองแบบถูกยกเลิก: Developer environment เริ่มระงับ 15 ธ.ค. 2026 / เริ่มลบ 15 ม.ค. 2027, Dataverse for Teams ปิดถาวร 30 ต.ค. 2027) โปรเจกต์นี้ไม่ใช้ทั้งสองแบบ ต้องสร้างทุกอย่างใน Default environment
